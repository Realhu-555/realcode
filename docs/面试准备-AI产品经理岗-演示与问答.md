# 面试准备 · AI 产品经理岗（含系统演示预案）

> 用途：明天面试。文档分三部分——**演示怎么演**、**产品叙事怎么讲**、**高频问答怎么答**。
> 核心心态：产品经理面看的不是你代码多强，而是**你会不会把产品讲清楚：给谁、解决什么、为什么是你、怎么衡量、下一步做什么**。技术细节只用来证明"我做的不是 PPT，是能跑的 Demo"。

---

## 0. 先认清两个面试风险

1. **演示翻车风险最高**：你的系统依赖「后端 + 模型 API + 数据 + 可选 QGIS」四层。任何一层挂了，演示就砸。
2. **讲成技术汇报的风险**：对方是产品视角，你讲 41 个工具/LangGraph 他会走神。要讲"用户、场景、价值、指标"。

对策见第 1、2 节。

---

## 1. 今晚必做的 5 件事（演示保命清单）

1. **预演两遍**：用下面"三幕演示脚本"，完整走 2 遍并计时（目标 8~10 分钟，留 2 分钟讲指标）。
2. **录屏备份**：把演示录成 5 分钟左右的 mp4 存桌面 + 微信文件传输助手。现场一旦网络/模型/QGIS 出问题 → **直接放录屏**，不要当场修。
3. **准备静态截图兜底**：3~5 张关键截图（对话页面、出图结果、审批卡片、图层树变化）。哪怕全程没有网，你也能靠截图讲完故事。
4. **环境双方案定好**：
   - **A 方案（主）**：QGIS 已开 + 插件在跑 + live 引擎 → 演示"真实 GIS 里操作 + 审批"；
   - **B 方案（兜底）**：把 `.env` 的 `GIS_ENGINE` 改回 `geopandas` 重启后端 → 不依赖 QGIS，演示"读数据→分析→出图→问答"链路（这个链路产品上一样成立）。
   - 面试前一小时把两个方案都跑通一次，记住当前用的哪个引擎（`GIS_ENGINE` 那行）。
5. **三条演示指令背下来**（见 2.3），并且都提前各跑过一遍、确认产物能打开。

---

## 2. 演示脚本（三幕，8~10 分钟）

### 2.1 第一幕：开场定位（1 分钟，先讲产品再开软件）

> 我今天带了一个真实的 AI Agent 产品，不是原型。一句话：**让不懂 GIS 软件的人，用自然语言指挥 GIS 完成专业操作**。
>
> 目标用户是测绘/地信的生产人员，每天在 QGIS 里做数据编辑、空间分析、出图。他们的痛点是：操作专业、重复性高、工具参数记不住、新人上手慢。我的产品让用户"说人话 → 系统真去干活 → 结果看得见、可检查、可回滚"。

> ⚠️ 如果面试公司不是 GIS 行业：补一句"这是垂直行业的 AI Agent 案例，产品方法可以平移到任何专业软件场景，比如客服、财税、工程"。**产品经理面试考的是方法，不是行业。**

### 2.2 第二幕：演示 2~3 个场景（5~6 分钟）

开场白固定句式：**"我会演示三种递进的能力：看得懂、会分析、能操作。"**

**场景 1：看得懂（30~40 秒，最快建立信任）**
> 指令："当前 QGIS 工程里有哪些图层？各是什么坐标系、多少要素？"
> 讲点：Agent 能感知真实环境（不是 demo 死数据）；回答会带回数据源。

**场景 2：会分析（1~2 分钟，主推）**
> 指令："加载 `data/gis_base/china_province.geojson`，按字段做一次字段统计，然后按 GDP 做一个分级设色图，解释一下分布。"
> 讲点：链式任务（读→算→画→讲）；**图是即时预览的**；这一步最稳、最能讲指标。

**场景 3：能操作 + 安全（2~3 分钟，差异点，需要 QGIS）**
> 指令："把当前图层复制为 bak，开始编辑，把 name 为'广东省'的要素某字段改成 0，提交并导出。"
> 讲点：**人工审批**——危险操作弹审批卡，你点"同意"它才执行（现场点一次给面试官看）；编辑可提交可回滚；结果**真的出现在 QGIS 图层树**里。
> 这句话要配台词："注意看，这是产品里最关键的交互——AI 要动我的数据，必须先经过我确认。这是企业用户敢不敢用的核心。"

> 若现场无法用 QGIS：场景 3 换成"演示审批流程 + 放一段录屏"，讲法不变。

### 2.3 三条备用指令（提前跑通）

| 指令 | 目的 | 预期产物 |
|---|---|---|
| "加载省界数据，统计字段，做分级设色图" | 最稳的链式展示 | 出图 PNG 即时预览 |
| "这个省的数据和那个市的点数据做空间连接，看每个省覆盖多少个市" | 空间分析能力 | 结果图层/表 |
| "加载数据→编辑→审批→提交→导出" | 操作 + HITL 安全 | 审批卡片 + 图层变化 + GeoJSON |

### 2.4 第三幕：收尾讲价值与指标（1~2 分钟）

演示完马上收，别等技术问答：

> 这套 Demo 背后我的产品判断是：**AI 进专业软件的路径不是"聊天"，是"干活 + 审批 + 留痕"**。它的价值不是替用户回答问题，而是把重复性专业操作的时间从"小时"压到"分钟"，并且每一步都可审计、可回滚——这对数据安全要求高的行业是能不能用的底线。
>
> 衡量这个产品，我不看"回答好不好"，看三个指标：**任务完成率**（说一件事能不能做成）、**人工介入率**（有多少比例的操作需要人再改）、**单任务耗时**（对比人工做）。我目前已经在建评测集来量化前两个。

## 3. 产品叙事一页纸（面试官任何角度问，都回到这张表）

| 问题 | 你的答案 |
|---|---|
| 给谁用 | 测绘/地信生产人员（内业，天天用 QGIS 画图改数据的人） |
| 什么场景 | 数据准备→空间分析→出图→编辑→入库 的重复性专业操作 |
| 解决什么痛点 | 专业软件操作门槛高、重复、易错、带人成本高 |
| 为什么用 AI Agent | 这类任务不是"搜索答案"，是"一连串有状态的操作"，只有 Agent 能闭环 |
| 为什么能做成 | 工具是可枚举的（41 个标准能力）、操作是可审批的、结果是可校验的 |

| 商业模式（被问再说） | 垂直行业可私有化/内网部署（测绘数据涉密），按座席/按任务收费，先做行业标杆客户 |
| 现在到哪一步 | 功能 Demo 完整可用（读/析/图/编辑/3D），测试 407 例全绿，正在做基准评测与真实环境验证 |

## 4. AI 产品经理高频问答（逐个准备）

**Q1：你怎么验证这个需求是真的，而不是你拍脑袋？**
> 我不是从"AI 能做什么"出发，是从"用户每天在干嘛"出发：我把自己代入内业生产人员的一天，列出 20+ 个真实任务（加载/编辑/质检/出图），发现重复操作和质检是最高频、最疼的。下一步的验证动作是：拿 3 个高频任务找真实用户跑通，看他愿不愿意每天打开——**用完愿意持续用，才是真需求**。

**Q2：竞品是谁？你做得好在哪？**
> 直接竞品是 ESRI ArcGIS 的 AI 助手（大厂在做）和把 QGIS 做成脚本批处理的工具。我的差异点：一是**不是问答是操作**，结果落在真实工程里；二是**人工审批 + 回滚**，企业敢用；三是**垂直轻量**，不绑定商业 GIS，开源生态可以私有化部署。大厂的优势是渠道和生态，我的窗口期是"专业软件 + Agent + 安全"这个组合还没人做透。

**Q3：这个产品最重要的指标是什么？为什么？**
> 北极星是**任务完成率**：用户说的任务，系统真正做成的比例。因为它同时衡量"AI 理解对不对"和"工具执行对不对"，也是用户会不会继续用的前提。辅助看人工介入率（安全与质量）和单任务耗时（价值）。

**Q4：如果效果不好/用户不满意，你怎么排查和迭代？**
> 我的排查是"看轨迹不看感觉"：每轮对话都留了 Agent 的执行轨迹（调了什么工具、参数、哪步失败），失败分两类——理解错了（改 prompt/意图）还是执行错了（改工具/节点）。改完跑回归用例，防止改好 A 弄坏 B。这套流程我在项目里就是这么做的。

**Q5：你会砍掉哪些功能？**
> 我会砍掉"看起来很酷但不进主流程"的功能，比如最初追求的多 Agent 流水线和花哨的 3D 可视化——它们验证的是技术不是需求。产品早期只保留"读数据→分析→出图→编辑→交付"这条主线，把这条线做深做稳。

**Q6：如果让你从零规划一个 AI 客服产品，你第一周做什么？**（如果对方业务是客服/通用 Agent，命中率极高）
> 第一周不做开发，做三件事：盘点（把现有流程、FAQ、转人工规则变成结构化的意图清单）；立评测（拿 50~100 条真实对话建小标注集，定"意图对不对/该不该转人工/话术合不合规"）；跑基线。**先能量化"现在有多差"，才知道 AI 改没改好。**

**Q7：AI 产品经理和普通 PM 区别？你怎么理解？**
> 普通 PM 定义"流程和交互"，AI PM 还要定义"能力边界和兜底"：AI 会犯错，所以产品必须有兜底设计（转人工、审批、拒答）；AI 效果要靠评测集和回归而不是拍板；AI 的成本（token/延迟）也是产品参数，要纳入决策。我的项目里这三点都实际处理过。

**Q8：最自豪/最难的一个决策？**
> 从多 Agent 流水线重构成单 Agent 工具调用。当时花了功夫做多 Agent，但真实任务发现链式任务状态强耦合、拆开反而更慢更难排查，我把它砍掉重做，换来的是稳定和可控。**这个经历说明我会为了产品目标推翻自己的技术方案**——这是产品经理最重要的素质之一。

## 5. 演示翻车急救表

| 症状 | 处理 |
|---|---|
| 模型 API 超时/没网 | "稍等，我切到备用方案"→ 放录屏 / 讲截图 |
| QGIS 没开/插件没了 | 用 B 方案（geopandas 引擎）演示只读链路；操作部分放录屏 |
| 指令答错/做错 | 不辩解，说"看，它失败了——这正是我要讲的：失败会留轨迹，能回滚、能改进"，反而加分 |
| 审批卡没弹 | 可能切了 auto 权限，口头补"这里应该弹审批，我演示前设成了自动" |
| 忘了词 | 看一页纸定位表（第 3 节），从"给谁、解决什么"重新起 |

## 6. 临场提醒

- 语速放慢，每个演示前先说要展示什么能力（"接下来看它会不会分析"），演示完补一句价值；
- 不报没跑出来的数字；被问准确率，口径 = 407 测试 + 评测集方法（见另一份面试文档）；
- 面试官大概率不懂 GIS——**每次你一说 GIS 名词，紧跟一句大白话解释**；
- 你最大的差异化是"能跑的 Demo + 会讲产品取舍的人"——市面上大多数 AI PM 候选人只有 PPT。
