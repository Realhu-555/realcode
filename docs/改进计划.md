# 改进计划 · 从分析型到操作型（保存分析型）

> 配套文档：`docs/GIS-智能操作助手-操作能力规划.md`（操作能力细节与 Gate 6-9）｜`docs/GIS-助手工程化与上线方案.md`（工程化）
> 本文档是**改进总览**：记录项目从「分析型 GIS 助手」升级为「操作型 GIS 智能操作助手」的定位转变、已完成改进、待办路线与改进原则。
> 版本：v0.2 ｜ 日期：2026-08-23 ｜ 作者：胡贞虎（新增 HITL 审批机制）

---

## 0. 一句话结论

- 定位从**分析型**（只能问数据、出报告）升级为**操作型**（像人一样操作 GIS 系统：编辑要素、管理图层、定制样式、排版出图、管理工程）；
- **保存分析型**：现有 20 个分析工具全部保留并继续扩展，操作能力是新增主线；
- 已完成的工程化与可靠性改进照旧生效，操作能力按 Gate 6-9 分阶段落地。

---

## 1. 定位转变（为什么）

| 维度 | 分析型（旧） | 操作型（新） |
|---|---|---|
| 交互 | 问 → 算 → 答 | 指令 → 操作 GIS → 交付 |
| 数据 | 只读分析 | 可读可改（增删改要素） |
| 界面 | 背后计算 | 操作用户眼前的 GIS 工程 |
| 价值 | 汇报材料、统计报表 | 替人干活：改图、整理数据、出图 |
| 天花板 | 问它要数据 | 让它干活 |

> 只有数据分析能力，不够"智能助手"；真正意义上的智能助手应能**操作系统本身**。分析能力保留（它是操作能力的一部分），操作能力是新主线。

## 4. 改进原则（约束）

1. **保存分析型**：分析工具保留并继续扩展（`run_algorithm` 白名单），不因加操作而削弱分析；
2. **安全边界不变**：危险操作（编辑/删除/覆盖）必须审批；不暴露任意脚本执行；
3. **双入口共享**：新工具一律走「schema + 引擎方法 + MCP handler」，Agent 与 dsh 自动共享；
4. **测试全绿**：每个改进带测试，质量门禁 `scripts\check.bat` 通过；
5. **按场景驱动**：操作能力优先做真实业务（测绘/应急/规划）高频操作，不一次性堆全。

## 6. HITL 审批机制（Human-in-the-Loop）

> 目标：危险操作（编辑/删除/覆盖/外部连接）必须**人在回路确认**，不能由模型自动执行；同时提供**权限模式选择**（对应"选择 agent 的权限"）。

### 6.1 权限模式（会话级可切换）

| 模式 | 行为 | 适用 |
|---|---|---|
| `readonly` | 所有写操作直接拒绝 | 演示/只读场景 |
| `ask`（默认） | 危险操作弹审批，人确认后才执行 | 生产/默认 |
| `auto` | 危险操作自动通过 | 可信环境/自动化 |

前端顶部下拉切换，后端 `permission_mode` 存会话。

### 6.2 后端 ApprovalGate

1. **危险操作注册表**：工具 → 审批级别（`destructive`/`medium`/`safe`）；`schema` 标记 `destructive: true`；
2. **执行拦截**：agent 执行危险工具前查权限模式：
   - `readonly` → 拒绝；`auto` → 放行；`ask` → 挂起，返回 `pending_approval`（含 id/工具/参数/预估影响）给 LLM，同时通知前端；
3. **审批接口**：`POST /api/v1/gis-assistant/approvals/{id}`，body `{action: "approve"|"reject"}`；
4. **超时兜底**：`default_on_timeout=reject`（默认 60s），避免挂死；
5. **审计**：审批记录（谁/何时/操作/结果）写入轨迹。

### 6.3 前端 HITL 交互

1. **审批卡片**：对话流中出现审批卡片（工具名、参数、影响数）→「允许 / 拒绝」按钮 → 调审批接口 → agent 继续；
2. **权限模式选择**：顶部下拉（只读 / 询问 / 自动）；
3. **审批状态展示**：pending（等待审批）/ approved / rejected。

### 6.4 工具对接范围（首批）

- 未来 Gate 6 的 `add_features` / `update_features` / `delete_features` / `commit_edits`；
- 现有产物覆盖写（同文件再次导出）等；
- 分析/只读工具不受影响。

### 6.5 验收

- 对话中触发危险操作 → 前端出现审批卡片 → 允许后执行 / 拒绝后 agent 收到 rejected；
- 三种权限模式行为正确；超时默认拒绝；审批记录入轨迹。
