## 0. 这份文档解决什么问题

把目标用户从「会 GIS 的任何人」收窄为**数据生产人员（内业，类似 CAD 画图员）**，
并回答三件事：

1. 他一天的真实工作是什么（任务清单）；
2. 这些任务对应助手的哪些能力（工具映射 + 缺口）；
3. 用哪几个任务当「验收标准」来判断助手真的有用。

> 作用：不是产品文档的全部，而是**验证标准**——下一轮评测、演示、迭代都围绕这几个任务转。

---

## 1. 目标用户画像

| 项 | 描述 |
|---|---|
| 身份 | 测绘/地信内业生产人员，天天在 QGIS/ArcGIS/CAD 里生产数据 |
| 日常产出 | 点/线/面矢量、属性表、质检报告、成果图、入库数据 |
| 工作台 | 桌面 GIS（本项目 = QGIS），数据在本地工程/工作目录 |
| 交互习惯 | 习惯命令式操作（CAD 命令行、脚本批处理），不习惯为每次操作开浏览器 |
| 痛点 | 重复操作多、质检靠肉眼、格式转换繁琐、工具参数记不住、带新人成本高 |
| 对助手的核心期望 | 一句话把活干完，结果落在**当前工程里**，能验收、能回滚 |

> 由此得到的形态结论：**Web 对话是入口/工场，插件/引擎是手脚**（详见插件方案文档）。
> 这个人群不会把 web 当主力干活界面，但会把它当「下指令 + 看成果 + 审批 + 留痕」的地方。

## 2. 一天的典型任务清单

按一个数据生产员一天的时间线组织，每条任务给出：人话指令示例、对应能力、当前工具映射、缺口。

### 2.1 早上：数据准备与整理

| # | 人话指令示例 | 能力 | 现有工具 | 缺口 |
|---|---|---|---|---|
| P1 | 「把 `H:/甲方/xxx.shp` 加载进来，看看坐标系和字段」 | 加载 + 探查 | `load_data` / `inspect_data` / `get_crs` | 需要能读工程外任意路径（受白名单约束） |
| P2 | 「这个数据是 2000 坐标，转成 4326 存一份」 | 坐标转换 | `transform_coords` | — |
| P3 | 「两份数据字段对不上，按 `CODE` 字段关联起来」 | 属性连接 | `join_by_attribute` | — |
| P4 | 「把这一堆 CAD 的 dwg 转成 shp，字段映射按标准走」 | 格式转换 + 字段映射 | `export_geojson` 等 | **dwg/dxf 导入、字段映射规则库** |
| P5 | 「这两个图层空间上重叠的挑出来」 | 空间关系 | `overlay` / `join_by_location` | — |

### 2.2 上午中段：编辑生产（最高频）

| # | 人话指令示例 | 能力 | 现有工具 | 缺口 |
|---|---|---|---|---|
| E1 | 「开始编辑 `村界`，在 (116.4, 39.9) 加一个点，属性 name=测试」 | 增点 | `start_editing` / `add_features` | — |
| E2 | 「把 `name='北京市'` 的要素 `adcode` 改成 999」 | 改属性 | `update_features` | — |
| E3 | 「按字段 `TYPE` 计算新字段 `AREA_HA` = 面积/10000」 | 字段计算 | `calculate_field` | — |
| E4 | 「批量把 `等级` 为空的要素标记为 '待定'」 | 批量更新 | `update_features` | — |
| E5 | 「把图层 A 复制一份叫 A_bak 再做修改」 | 复制备份 | `duplicate_layer` | — |
| E6 | 「刚才改错了，回滚编辑」 / 「确认没问题，提交编辑」 | 事务 | `rollback_edits` / `commit_edits` | 需要**提示用户可能改错的范围**（HITL） |

### 2.3 午前/午后：质检（最容易被忽视、价值最高）

| # | 人话指令示例 | 能力 | 现有工具 | 缺口 |
|---|---|---|---|---|
| Q1 | 「检查 `道路` 图层有没有拓扑错误（重复、悬挂点）」 | 拓扑检查 | — | **topology 检查工具（native:topologychecker）** |
| Q2 | 「找出所有几何为空的、面积小于 0 的要素」 | 几何质检 | `delete_features` / `field_statistics` | **按规则质检 + 报告工具** |
| Q3 | 「看看 `属性` 表里 `ID` 有没有重复」 | 属性质检 | `unique_values` / `field_statistics` | 一键重复值定位 |
| Q4 | 「这两个相邻图层接边差超过 0.5m 的地方标出来」 | 接边检查 | — | **接边检查工具（高级）** |
| Q5 | 「按规范检查必填字段有没有空值」 | 规则质检 | `unique_values` | **质检规则配置 + 结果图层/报告** |

### 2.4 下午：统计分析与成果

| # | 人话指令示例 | 能力 | 现有工具 | 缺口 |
|---|---|---|---|---|
| S1 | 「按省汇总 GDP，出分级设色图」 | 专题图 | `choropleth` / `categorized` | — |
| S2 | 「对点做 500m 缓冲区」 | 缓冲区 | `buffer` | — |
| S3 | 「生成这些点的泰森多边形」 | 空间分析 | `voronoi` | — |
| S4 | 「加一个卫星底图，出张带图例指北针的 A3 图」 | 制图 | `load_basemap` / `layout_map` | 制图模板（**印刷出图规范**） |
| S5 | 「把统计结果导出成 CSV 和 GeoJSON」 | 导出 | `summarize` / `export_geojson` | — |

### 2.5 下班前：入库、归档与交付

| # | 人话指令示例 | 能力 | 现有工具 | 缺口 |
|---|---|---|---|---|
| D1 | 「按国标字段映射，把成果整理成入库结构」 | 标准化 | — | **字段映射模板 + 入库校验** |
| D2 | 「保存工程，成果文件列个清单」 | 工程管理 | `save_project` / `export_layer_inventory` | — |
| D3 | 「这版成果做个汇总报告给我」 | 汇报 | `summarize` | 报告模板（配合结果审核） |

## 3. 结论：哪些是「验证级」任务

结合当前 41 个工具已覆盖的能力，选 3 条**能立刻验收**、且代表「生产员真实活」的任务作为基准：

| 验收任务 | 覆盖任务 | 验收点 |
|---|---|---|
| **T1 全流程编辑**：「加载 xx 数据 → 新增点 → 改属性 → 按字段计算 → 提交，导出一份 GeoJSON」 | P1/E1/E2/E3/E6/D2 | 结果图层出现、属性正确、可回滚、可导出 |
| **T2 质检闭环**：「找出 `ID` 重复 + 必填字段为空的要求，出一份质检报告图层」 | Q2/Q3/Q5 | 能定位错误要素、产出报告（**当前最大缺口**） |
| **T3 空间分析与制图**：「加底图 → 500m 缓冲区 → 出带图例的 A3 图」 | S2/S4 | 底图 + 缓冲区结果入工程、出图可打开 |

> 评审口径：**在真实 QGIS 工程里操作**（不是 demo 数据），结果看得见、可下载、可回滚。

## 4. 工具缺口清单（供后续规划）

| 优先级 | 缺口 | 说明 |
|---|---|---|
| P0 | 规则质检工具（重复值/空值/几何非法 + 结果图层 + 报告） | T2 验收必需，当前工具是单字段统计，不是「规则集 + 一键跑」 |
| P0 | 工程外文件加载（路径白名单扩展 / 授权目录） | 生产员天天要读甲方数据，不能只读 `data/` |
| P1 | dwg/dxf → shp 导入 + 字段映射 | 测绘内业绕不开 CAD 数据 |
| P1 | 制图模板（按标准出图样式） | `layout_map` 已有，缺「模板复用」 |
| P2 | 拓扑检查（重复/悬挂/接边） | 依赖 QGIS native 算法，投入大 |
| P2 | 质检规则可配置化 + 历史规则复用 | 与长期记忆/程序性记忆结合 |

## 5. 落地方式

1. 把 T1/T2/T3 三条任务写进现有基准评测（`src/gis_toolkit/bench.py`），要求「QGIS 插件环境下通过」；
2. 插件 M1（可加载 + 状态注入）跑通后，先在插件里手工复现 T1；
3. T2 作为第一个**新增工具**的切入点（质检规则工具 + 结果图层），因为它最贴近生产员痛点、也是竞品很难做的一块；
4. 每条任务闭环后更新本清单的状态列（✅/🕐）。
